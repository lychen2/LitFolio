# Convert Legacy Library Data

## Goal

Convert every supported legacy LitFolio library at migration levels `0001`-`0035` into the final Mono core plus plugin-store layout with complete backup, verification, reporting, idempotence, and rollback.

## Dependencies

- `mono-reader-annotations`, `mono-provenance-reading`, `mono-ai-reading-core`, `mono-plugin-host-sdk`, and all plugin extraction children are completed and archived.
- Final core/plugin schemas, sidecar migrators, config owners, file-layout contracts, and the canonical manifest compiler/resolved-inclusion schema are frozen.

## Requirements

- Detect legacy schema/file/config state before normal writable application bootstrap and produce a deterministic conversion preview.
- Consume a versioned resolved inclusion plan generated by the canonical `PluginManifestV1` compiler. Caller-supplied plugin ID lists or converter-owned manifest metadata are not accepted.
- Bind preview and execution to the plan schema version, manifest-set digest, selected build profile, included owner versions, migrator/data-schema versions, and target core schema. Reject a missing, malformed, incompatible, or stale plan before backup or staging writes.
- Create a complete verified backup of database, WAL/SHM, core files, notes, vectors, attachments, config, secrets metadata references, provenance files, and plugin-relevant files before conversion.
- Write conversion output to a sibling staging root with a durable stage journal; never mutate the only source copy.
- Apply the core baseline, annotation/provenance converters, each included plugin migrator, config split, and file/archive mapping selected by the resolved inclusion plan.
- Convert margin-note sentinel rows to `pdf_notes`; preserve ordinary highlights; preserve original Markdown notes; export note sections to versioned legacy-note archives.
- Convert accepted document projections into core-owned document revisions/segments where evidence exists, and preserve source links, snapshots, backlink indexes, canonical Markdown/assets, and provenance export inputs independently of `document-services` inclusion.
- For an included-but-runtime-disabled plugin, migrate data to its sidecar and preserve disabled state without activation. For a build-excluded plugin, create a reversible owner archive instead of creating an active sidecar or dropping data.
- Every sidecar and excluded-owner archive records owner/plugin version, source/target schema, manifest-set and inclusion-plan digests, migration IDs, file inventory, row/file counts, checksums, unresolved references, and restoration requirements.
- Preserve stable IDs and cross-plugin scalar references, including Ask-session project IDs and evidence annotation snapshots.
- Verify row/file counts, required fields, reference reports, checksums where applicable, target schema versions, provenance indexes, and archive manifests before atomic switch.
- On any failure, leave/restore the original library and emit a redacted actionable report. A successful rerun creates no duplicates.
- Refuse unsupported future schemas, concurrent writers, insufficient disk, unsafe paths, corrupt source data, unverifiable backups, or a plan that changes before switch.

## Constraints

- Historical migrations `0001`-`0035` are byte-for-byte unchanged.
- Conversion cannot require network or an AI profile.
- User confirmation follows preview/backup planning before the one-time switch; normal library writes remain locked during conversion.
- No legacy data is deleted as cleanup in this task; removal requires a later separately confirmed retention policy.
- The converter consumes compiler output and feature-neutral owner descriptors; it does not define a second manifest compiler or require excluded plugin runtime code.

## Out of Scope

- Feature extraction, schema redesign after freeze, or visual redesign.
- Syncing converted data to a remote service.
- Deleting backups/archives automatically.

## Acceptance Criteria

- [ ] Fixtures produced at every migration boundary `0001`-`0035` convert to the expected core/plugin/archive state.
- [ ] Mixed notes, files, plugin data, absent plugins, missing references, and legacy config/secrets metadata all appear in the report with no silent loss.
- [ ] Matching resolved plans produce deterministic previews; forged plugin lists and plans with stale schema, profile, manifest, owner, migrator, or target-schema digests fail before backup/staging writes.
- [ ] Included-but-disabled fixtures populate verified sidecars without activation; excluded-owner fixtures populate reversible archives, preserve runtime state, and restore after later compatible inclusion.
- [ ] Accepted document revisions/segments, source links/snapshots/backlinks, canonical Markdown/assets, and provenance export inputs survive conversion and remain usable in core-only and `document-services`-excluded fixtures.
- [ ] Backup integrity is verified before write; injected failures at every stage restore/leave a byte-equivalent usable legacy library.
- [ ] Successful conversion atomically activates the new layout and a second run is a no-op with matching counts/checksums.
- [ ] Unsupported/corrupt/concurrent/insufficient-space/path-unsafe cases fail before destructive switch with structured errors.
- [ ] Conversion runs fully offline and never logs secrets or user document contents beyond bounded identifiers/counts.
- [ ] Focused converter/storage tests, full Cargo tests, frontend migration-state tests, and upgrade E2E pass.
