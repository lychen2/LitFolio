# Convert Legacy Library Data - Design

## 1. Scope / Trigger

Run once when startup detects a supported legacy layout and before normal writable `AppState` is created. The converter uses final schemas from all preceding children and is the only cross-owner migration orchestrator.

## 2. Signatures

```rust
struct ConversionPreview {
    source_version: u32,
    required_bytes: u64,
    backup_path: PathBuf,
    inclusion_plan: InclusionPlanRef,
    planned_owners: Vec<OwnerPlan>,
    warnings: Vec<ConversionWarning>,
}

struct InclusionPlanRef {
    plan_schema_version: u32,
    manifest_schema_version: u32,
    manifest_set_digest: String,
    profile_id: String,
    profile_digest: String,
    target_core_schema: u32,
    compiler_version: String,
}

enum OwnerDisposition {
    Core,
    IncludedEnabled,
    IncludedDisabled,
    ExcludedArchive,
}

struct ConversionReport {
    id: String,
    source_version: u32,
    target_version: u32,
    stage: ConversionStage,
    inclusion_plan: InclusionPlanRef,
    per_owner: Vec<OwnerCounts>,
    provenance: ProvenanceVerification,
    archives: Vec<ArchiveManifest>,
    unresolved: Vec<UnresolvedReference>,
    backup: BackupVerification,
    rollback: Option<RollbackResult>,
}

enum ConversionStage {
    Detected, Preflighted, BackedUp, Staged, Verified, Switched, RolledBack,
}
```

Coordinator operations:

```text
detect(root) -> LegacyState | CurrentState | UnsupportedState
preview(root, resolvedInclusionPlan) -> ConversionPreview
run(previewToken) -> ConversionReport
status(conversionId) -> ConversionReport
```

Each owner exposes an idempotent migrator with `plan`, `convert`, and `verify` against staging.

`ResolvedInclusionPlan` is generated by the canonical manifest compiler owned by `mono-plugin-host-sdk`. This child imports its validated schema and does not define manifests, resolve dependencies, or accept a replacement plugin-ID list. The preview token commits to the complete plan digest, runtime enabled-state snapshot, and source fingerprint.

## 3. Contracts

- Acquire an exclusive conversion lock and prove no live writer before backup.
- Validate the plan schema and recompute the canonical manifest-set, profile, owner, build-entry, data-schema, migrator, and target-schema digests before any write and again before switch.
- Source root is treated read-only. Staging and backup are siblings on the same filesystem where possible for atomic rename.
- Backup includes DB/WAL/SHM and all conversion-relevant files; its manifest stores size/hash and source-relative path without secrets/content in logs.
- Disk preflight accounts for backup plus staging plus safety margin.
- Stage journal is fsynced at boundaries, contains the inclusion-plan digest, and survives process interruption.
- Owner migrators are deterministic, idempotent, version-matched to the plan, and cannot write outside staging.
- Core provenance conversion covers accepted document revisions/segments, source links/refs, immutable snapshots, backlink indexes, canonical Markdown/asset handles, remap status, and export metadata regardless of parser-plugin inclusion.
- Included-enabled and included-disabled owners run the plan-selected migrator into a sidecar. Runtime-disabled state is preserved and conversion never activates the plugin.
- Excluded owners use feature-neutral conversion descriptors to produce a reversible archive; no runtime plugin code or active sidecar is required. The archive records manifest/inclusion digests, owner/version/schema, migration IDs, source-relative files, counts/checksums, unresolved references, and compatible restore requirements.
- Verification completes before switch. Handles are closed, source is renamed to backup location, and staging is atomically renamed into place.
- If switch fails, rename back and verify legacy startup. Original backup is never deleted automatically.
- Secrets remain in keyring; only config references/ownership metadata move.

## 4. Validation & Error Matrix

| Condition | Result |
| --- | --- |
| schema `0001`-`0035` | supported preview/plan |
| missing/malformed inclusion plan | `conversion_invalid_inclusion_plan`, no backup/write |
| manifest/profile/owner/migrator/target digest changed | `conversion_stale_inclusion_plan`, no backup/write |
| unknown future schema | `conversion_unsupported_version`, no write |
| active writer/lock | `conversion_library_busy`, no backup/write |
| insufficient space | `conversion_insufficient_space`, no write |
| unsafe/symlink escape path | `conversion_unsafe_path`, no copy |
| corrupt DB/file | `conversion_source_corrupt`, report item, no switch |
| backup hash mismatch | abort before staging/switch |
| owner migrator fails | staging discarded/retained for diagnostics; source untouched |
| provenance/index/archive count or hash mismatch | no switch |
| process dies per stage | resume safely or rollback based on durable journal and matching plan |
| atomic rename fails | restore original name and verify; report rollback |
| second run after success | current-state no-op |

## 5. Good / Base / Bad Cases

- Good: a `0035` library with all data and only some plugins included produces core/sidecars/archives, verifies, switches atomically, and reruns as no-op.
- Base: a `0001` core-only profile converts entirely offline; accepted provenance remains core-owned and every excluded owner is represented by a reversible archive.
- Bad: an ad hoc plugin ID list selects migrators, or in-place `ALTER`/`DELETE` operations run against the only `library.db` before plan and backup verification.

## 6. Tests Required

- Generate fixtures by applying each historical migration prefix `0001` through `0035`, then seed representative data for tables present at that boundary.
- Mixed annotation/note/provenance/config/vector/attachment/supplement/project/Ask/reference fixtures.
- Included-enabled/included-disabled/excluded plugin matrix, runtime-state preservation, stale-plan rejection, and archive restoration tests.
- Provenance table/file/count/hash fixtures, including `document-services` excluded after accepted documents exist.
- Backup/WAL/SHM/file manifest, disk-space, lock, corrupt source, future schema, unsafe path, and secret-redaction tests.
- Failure injection after every durable stage plus process-interruption resume/rollback.
- Count/hash/reference verification and second-run no-op.
- Startup/migration UI E2E from old library to core/all-plugin layouts.

## 7. Ordered Conversion

1. **Resolve**: load compiler output, validate all digests, classify every owner disposition, and bind the preview token.
2. **Preflight**: lock, detect, inventory, path safety, source integrity, disk estimate.
3. **Backup**: copy DB/WAL/SHM/files/config, fsync, hash, verify.
4. **Stage**: create target schemas; run core, provenance, included-owner, and excluded-archive converters.
5. **Verify**: target integrity, provenance indexes, counts, references, sidecars, archives, config ownership, and secret references.
6. **Revalidate plan**: reject changed manifest/profile/schema/migrator inputs before target activation.
7. **Switch**: close handles, rename source, rename staging, reopen/verify.
8. **Report**: persist plan/source/target digests, owner dispositions, backup, conversion, archive, rollback, and no-op evidence.

## 8. Wrong vs Correct

Wrong:

```rust
preview(root, vec!["document-services"])?;
sqlx::migrate!().run(&legacy_pool).await?;
```

Correct: consume the canonical resolved inclusion plan, reject drift, open source read-only, verify backup, convert core provenance plus selected sidecars/archives into staging, verify the complete target, close handles, and atomically switch roots.
